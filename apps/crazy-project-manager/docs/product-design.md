# 疯狂的项目经理

**逆向 UX 挑战赛 · 产品需求与技术总体设计 · v0.1**

玩家是海报项目经理。周总想让人记住展名，林尺盯着被贴纸盖住的馆标，阿唐担心观众到了门口才发现要预约。三个人都可以说得模糊，也可以互不让步。玩家要决定问谁、听谁、把哪句话交给员工小乙，以及哪一版值得交付。

**定稿权在项目经理手里。** 每位甲方有一条 0–100 的满意度，用来表达这张海报在其立场下做得怎样。只要已有可导出的海报版本，任何分数组合都可以交付，包括甲方还在争吵、需求尚未问清，或经理有意搁置一条意见的情况。导出记录绑定当时选择的版本。

## 1 产品价值与首发范围

这款应用给需要替客户做海报的人用。真实工作里耗时间的，常常是把“高级一点”翻译成能动手的改动，以及向另一位客户解释为什么这样改。应用把这段工作放进同一个工作台，给经理留下三种可用的成果。

| 经理需要解决的问题 | 一局结束后拿到什么 |
| --- | --- |
| 客户到底要什么 | 按角色整理的需求清单，能从经理的改写追溯到甲方原话，也看得出哪些还模糊、哪些有冲突。 |
| 改一处会让谁不满意 | 与海报版本对应的评审记录，包含三方的意见、分项得失、争议元素和经理的取舍。 |
| 今天究竟交哪张图 | 经理选定的海报，可下载 PNG 或可编辑 SVG。需要解释过程时，可以打开整局回放。 |

首发建议采用桌面 Web，以“夜游美术馆”跑通一个完整主题。每个项目绑定自己的主题简报、初稿、活动文案、素材、图层和评分规则。参赛版先做透一张可反复改的主题海报，后续主题沿用同一套派工、评审和回放流程。

## 3 一局怎样进行

1. **接项目。** 选定主题，系统从模板生成可编辑的 V01。以“夜游美术馆”为例，经理能看到展名、馆名、展期、时段，以及“免费但须预约、东门入场”的活动事实。
2. **听需求。** 三张角色卡各给一句开场意见。经理可以定向打字或按住麦克风追问，也可以当场转交某句话。三人可以对同一块画面提出彼此冲突的要求。
3. **决定怎么派工。** 经理可原样转发、编辑后转发，或合并多条意见。工单同时保存来源消息、经理指令、目标元素和基础版本。暂时搁置的意见仍可回来处理。
4. **看小乙改图。** 小乙说明要改的地方，调用海报工具。遇到摸鱼，经理可以拍桌，也可以用文字或语音叫他继续。成功改稿后，中间画布出现新版本，可与上一版对比。
5. **看反应，再作决定。** 每次实质改动都触发三方对同版的评审。经理可以打断争吵、追问理由、再派一单、恢复某个旧版，或直接定稿导出。小乙正在改图时，也能交付上一个已经生成的版本。

### 三种挫败分别发生在哪里

| 机制 | 刻意让人抓狂的地方 | 设计用意与可行出路 |
| --- | --- | --- |
| 需求只说半截 | “高级一点”没有目标元素。原样转给小乙，他会反问“你要我动标题、主图，还是颜色？” | 让玩家承担翻译需求的成本。追问应揭示真实信息，例如“让展名先被看见”。经理也可以自行解释并派工，承担解释偏差带来的分数变化。 |
| 三方围绕同一处争吵 | 放大预约贴让阿唐加分，周总嫌它抢标题，林尺发现它挡住馆标。一次成功修改也能招来两句反对。 | 把多方诉求的代价画在海报上。每句反驳指向先前发言和具体元素。经理能试折中版，也能保留偏向某一方的版本。 |
| 员工在半途摸鱼 | 小乙的进度停在 50%，还说“这个视频就 15 秒……真的。”经理得从争执中抽身管执行。 | 拍桌后立刻出现 QAQ 与抱怨，同一工单从原处继续。每单最多停一次，按钮、键盘、文字、语音均可复工。 |

## 4 角色与交互约定

| 角色 | 自己关心的事 | 从模糊意见到具体动作 |
| --- | --- | --- |
| **周总 · 老板** | 观众先看到什么，最后记住什么。说话短，习惯现场拍板。 | “高级一点。”问他想让人记住什么，他会说“展名”。再问哪处抢眼，他会指出标题旁的黄贴，建议缩成手机尺寸试看。 |
| **林尺 · 品牌负责人** | 授权标志、署名、配色、留白和发布时的辨识度。先报位置或文件。 | “按联名规范走。”追问后指出馆标用了旧版，再给出本场适用的白标、可放位置和净空要求。资料缺失时说明缺哪一份。 |
| **阿唐 · 客户方活动负责人** | 观众能否看懂参与条件、找到入口、从正确的门入场。 | “几个卖点都要突出。”追问后具体到“免费和须预约要放在一起”。只要手机预览可读，他能接受放到底部。 |
| **小乙 · 执行设计师** | 把经理选中的意见变成具体改图动作。会抱怨，也会交稿。 | “字号我能改。你说的‘更有感觉’，想先试标题还是配色？”收到明确指令后按工单改图，并报告改了哪些图层。 |

**追问与转交。** 角色卡显示原话、最近一次具体要求和关联元素。追问可以逐步揭示“目标 → 元素与条件 → 可让步的地方”。经理可随时离开这条对话。提问入口提供可点的具体问题，重复问候也留下记录。来源不清的工单由小乙回问一件最影响执行的事，经理仍可以改派其他任务。

**有来有回的争吵。** 每版先汇总三方的分数和理由，让受影响最大的角色先开口，持相反意见的人引用他刚说的话，第三人说明这处改动怎样影响自己。每版最多三条首评、两条反驳。已解决的问题只在相关图层或证据再次变化时重开。经理点“打断”或发送新问题时，话筒立即让出。

**小乙的工作状态。** 待命 → 已接单 → 工作中 → 可选的摸鱼暂停 → 继续工作 → 交稿或报错。沿用原型的奇数工单 50% 暂停作为演示规则。拍桌热区、按钮及输入框外的空格都能触发“啪！”和约 750 毫秒的 QAQ。“快一点，继续刚才那张”走相同的恢复逻辑。空闲时拍桌只触发表情和台词，连续拍击可留多次动作记录，同一工单只恢复一次。静音或减少动画时用字幕表达同一反馈。

## 5 每位甲方怎样给出自己的 100 分

每个人独立对**同一个海报版本**评分。分数衡量海报与这个角色诉求的符合程度。卡片展示当前分、较上一版的变化、得失分项，以及能点选定位的画面元素。经理能看到“阿唐 +15，预约条件更好找”，也能看到林尺为何同时减了 35 分。

| 甲方 | 分项权重（每行合计 100） | 取证示例 |
| --- | --- | --- |
| 周总 | 标题与第一眼 **40**，主视觉与活动目标 **25**，布局主次 **20**，文字编排 **15** | 在固定手机预览尺寸查看展名与黄贴的视觉权重，核对主图主题、断行和边界。 |
| 林尺 | 授权标志和用法 **35**，正式署名 **20**，已确认的品牌版式及配色 **20**，实际辨识度 **25** | 比对主题素材 ID、标志比例、遮挡、署名全称与顺序，再检查发布尺寸上的对比和净空。 |
| 阿唐 | 活动事实与参与条件 **35**，关键信息是否好找 **30**，实际参与入口 **25**，卖点取舍 **10** | 比对简报中的时间、地点、费用和预约要求。用当前导出图解码二维码，核对目标测试页是否可达。 |

### 计分与证据

- 每项按“满足、部分满足、未满足”取 **1、0.5、0**。适用项都有证据时，**满意度 = 四舍五入（100 × 各项已得分之和 ÷ 适用项权重之和）**。主题明确不涉及的项目从分母剔除。例如无预约入口的主题可剔除阿唐的 25 分，其余 75 分折算到 100。每个主题为每位甲方至少配置一个适用项。
- 每项由主题给出可复查的三档样例。例如林尺的“标志和用法”在使用指定素材、无遮挡且比例正确时得 35 分，只有净空不足时得 17.5 分，使用旧标或标志被遮挡时得 0 分。一次遮挡只归到这项。周总和阿唐仍可按各自立场评价同一张贴纸。
- 甲方可以一直保留模糊的偏好。计分采用该角色的主题标准，以及后来已说清、有证据可核的条件。经理可以选择忽略，角色仍按自己的立场打分。条件变更单独记录，改图前后的分差采用同一套规则比较。缺素材或缺测试证据的适用项标“待验证”。优先显示上次有依据的分数及其版本，首次无历史时显示已证实分数下界与待验权重。证据补齐后再公布本版分数和差值。
- 三位 Agent 各自返回意见、关联元素、评分项和理由。规则服务根据图层、预览和工具证据计算分数，把本版的分项结果交给角色解释。相同画面、规则和证据应得到相同分数。玩家无需猜某个模型这次愿意打几分。

### 一张黄贴怎样得到三个相反的结论

下面按角色手册的示例前提演算。演示主题需补齐示例白标、合作方署名和能实际打开测试页的预约码。起点是展名与馆标表现良好、预约码已验证，但预约条件还不够好找的一版。以下数值用于首发评分规格，新版压缩包当前运行的是简化公式。

| 版本与动作 | 周总 | 林尺 | 阿唐 | 经理可以做什么 |
| --- | ---: | ---: | ---: | --- |
| A 版。预约条件在角落，阿唐的“好找”只得一半 | 100 | 100 | 85 | 听阿唐解释观众会漏看什么。 |
| B 版。小乙把“免费 · 须预约”做成标题旁的大黄贴，遮住半枚馆标 | **80（−20）** | **65（−35）** | **100（+15）** | **直接导出 B 版。** 交付记录保留林尺的反对意见和导致扣分的遮挡位置。 |
| C 版。经理也可以再改，将黄贴移到预约区。在手机预览中复核可读性与馆标，重新验证入口 | 100 | 100 | 100 | 在示例各项证据均满足的前提下得到这组分数。经理可选 C 版，也可回选 B 版。 |

争执可以很短。阿唐说“这回观众看见须预约了。”周总接“他看完记住的是免费，展览叫什么？”林尺再指向右上角“你们先把我的半个馆标还回来。”三句话都在说同一块黄贴，玩家马上知道该回画布看哪里。

## 6 系统骨架与改图工具

黑客松版建议使用一个 Node.js 会话服务。浏览器处理输入、即时表情和播放，服务端负责四个角色的调度、海报版本、评分与持久化。三个甲方可以并行准备首评，经理点名单独提问时只调起被点名的角色。每份海报同一时刻由一个小乙工单写入。

~~~mermaid
flowchart LR
    UI["新版三栏工作台"] -->|经理命令或语音| Hub["会话服务"]
    Hub -->|定向提问或同版评审| Clients["周总、林尺、阿唐"]
    Clients -->|意见、元素、理由| Hub
    Hub -->|经理已派工单| Worker["员工小乙"]
    Worker -->|结构化修改| Tool["图层校验与海报渲染"]
    Tool -->|新版本与预览| Hub
    Hub <--> Voice["语音识别与配音"]
    Hub -->|事件与版本| Store["SQLite 与本地资源文件"]
    Hub -->|字幕、分数、媒体与状态| UI
    Store --> Player["离线回放器"]
~~~

### 图怎么真正改出来

每个主题的初稿是带稳定元素 ID 的场景。展名、馆标、署名、黄贴、入场文字和预约码可分别定位。小乙的工具接收工单、基础版本和修改列表，可改文字与样式、移动或分组元素、替换主题素材。经理说“黄贴放到预约码旁边，别动馆标”，相应补丁只应触及黄贴及其布局关系。

执行器在副本上校验元素与坐标，渲染可见预览并记录前后差异。合法但引发遮挡的改动应能出图，交给林尺提出异议。工具参数无效、素材损坏或渲染失败时则保留上一版，小乙指出哪一步失败。同一工单重试至多提交一次新版本。V01、历次修改和导出的 SVG／PNG 均引用同一个版本化场景，避免分数算在 B 版、用户却拿到 A 版。

### 各模块交接什么

| 交接对象 | 最少应携带的内容 |
| --- | --- |
| 主题与会话 | 主题 ID、简报版本、发布尺寸、事实与素材、规则版本、初稿、在线或本地演练模式。 |
| 甲方发言与需求 | 角色、原话、关联版本与图层、引用的上一句、已揭示条件、让步项、已有证据。模糊或互相冲突的意见可长期并存。 |
| 工单与版本 | 原话引用、经理改写、指令 ID、基础版本、员工状态及检查点。新版本另存父版本、工具参数、图层差异、预览与文件哈希。 |
| 评审与交付 | 三方各自的版本、分数、分项、证据、变化原因。交付记录另存经理选择的版本和输出文件。评分尚在生成时，导出仍可完成。 |

命令可走 HTTP，字幕和状态用服务端推送事件（SSE），双向语音走 WebSocket。会话事件有递增序号，断线重连后从已确认的位置补拉。重复命令返回原回执。旧版本的模型回复归到原版本，恢复旧稿另建版本并记录来源。文件先写入并校验哈希，再用 SQLite 事务一起提交版本、评分依据和事件引用。[HTML 事件流规范](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-last-event-id-header) · [SQLite 事务说明](https://www.sqlite.org/lang_transaction.html)

## 7 低延时交流

文字与语音都能发给甲方或小乙。按下麦克风时固定收件人，录音开始后切换角色也不会串话。默认松手发送，可选“先校对”来修改转写。玩家点麦克风插话时，本地先停旧声音，同时通知服务端取消旧话轮。迟到的分段按旧话轮归档。

下列为**拟定的 P95 验收目标**。开始计时以前的用户思考时间，以及用户主动停在摸鱼画面的时长，分别统计。

| 用户能感知的时间 | 从什么时刻量到什么时刻 | P95 目标 |
| --- | --- | ---: |
| 拍桌手感 | 点下桌面、按钮或空格，到 QAQ、震动或等价字幕的第一帧 | ≤ 80 毫秒 |
| 文字问答首段 | 经理发送，到目标角色首段有实质内容的答复显示 | ≤ 1.2 秒 |
| 语音识别收尾 | 松手，到最终转写可用 | ≤ 450 毫秒 |
| 语音问答首段 | 松手即发，到角色首段答复显示 | ≤ 1.6 秒 |
| 角色首音 | 文字发送或语音松手即发，到第一句角色声音实际开始播放 | ≤ 2.3 秒 |
| 插话 | 用户发出打断动作，到旧声音停止输出 | ≤ 150 毫秒 |

**关键链路。** 录音分块上传，同时显示临时转写。模型回复产出第一句经校验的内容就推字幕。配音按短句生成，第一段就绪即可播放，下一段同时预取。固定中文台词、QAQ 抱怨和拍桌音效预生成。动态音频缓存键覆盖文本、角色音色、情绪、语速和合成版本。三方意见可以并行准备，可听声轨一次只放一人，抢话以明确的切断事件衔接。

**降级仍能办事。** 麦克风被拒或识别失败时保留收件人，可打字继续。模型超过 2 秒未返回有效首句时可使用当前主题的具体答复，并标“本地演练”。TTS 超过 3 秒时选择同文的预制声音，缺少同文声音就保留字幕并标记本句静音。迟到的在线回复不重复上屏。无外网时，本地角色卡、工单配方和渲染器仍可走通改稿与导出。

**测量口径。** 首轮联调可用同一演示设备、10 Mbps 可用带宽、约 50 毫秒往返时延，分别测试单会话及三会话并行，文字和语音各至少 100 轮。用浏览器单调时钟记录真实首字、首音和停播，另报 P50、冷启动、缓存命中、超时和降级比例。模型回答与本地演练分开出表，超时记为未达标。选择人工校对的语音另从点击发送起算。

## 8 所有应用内操作都能重放

回到某一秒，观众应能看见经理当时选的是谁、小乙停在哪里、海报是哪一版、三人各有多少分，以及哪句话说到一半被打断。版本记录回答“改了什么”，回放还要回答“当时怎么操作、看见和听见了什么”。

| 需要记录的轨迹 | 典型内容 |
| --- | --- |
| 用户操作与界面 | 主题和角色选择、输入及修改草稿、语音校对、发送与撤销草稿、直接或编辑转发、点击与快捷键、连击及无效操作反馈、弹窗、悬浮提示、滚动、缩放、对比、切换与恢复版本、上传、静音、定稿和导出。 |
| 对话与实际声音 | 录音开始／取消／结束、实际音频、临时和最终转写、分段字幕、首评和反驳的引用、谁先开口、每段何时开始播放以及在音频的哪个位置被切断。 |
| 员工与海报工具 | 接单、进度、摸鱼、拍桌来源、QAQ 表情、抱怨、复工、工具参数与返回值、重试、真实图层差异、版本、分项得失与输出文件。 |
| 外部结果与运行环境 | 实际使用的模型回复、配音字节、素材与字体、演练模式、选中的话术或随机结果、错误、断线、重连、超时、降级和刷新后的恢复。 |

### 两条轨迹怎样对齐

- **业务轨迹**按会话递增的 `seq` 排序。事件带类型、角色、命令 ID、因果关联、海报版本、相对时间和数据。一次拍桌可以对应“收到桌面动作 → 小乙恢复 J01 → J01 产出 V02”，由同一个命令关联起来。
- **呈现轨迹**记录页面实例、客户端序号、单调时间、当时已呈现的业务序号和音频偏移。应用统一收集输入动作，在真正绘制字幕、表情或开始／停止播放时记录实际时刻。这样可以还原网络慢时用户曾经看到的停顿。刷新后为新页面建立时间锚点。
- 浏览器把待传动作放入 IndexedDB，确认后再移出队列。服务端按命令 ID 或客户端序号去重，事件与版本持久化后再广播。海报、上传原件和音频按 SHA-256 寻址。断线恢复只补缺段，重复收到“复工”不会再执行一次改图。

### 回放器的行为

导出一份回放时固定结束序号，校验已确认的呈现记录与资源清单。建议离线包内放一个只读播放器和会话数据文件，数据包含事件、快照、版本图像、声音、字体及动效版本。用户打开播放器，选中同包数据即可观看。首次录音前说明语音将随本局保存，可选择全程使用文字。

播放器支持暂停、逐步、拖动、倍速以及“跳到拍桌／冲突／某版海报”。每次改稿提交及每 100 条事件建立快照，包含草稿、界面位置、工单进度、分数和播放偏移。跳转时先加载最近快照，再顺序应用增量事件。回放使用当时保存的发言、声音与图像，下载、模型推理、语音合成和改图调用仅展示原结果。若音频只播到第 0.8 秒便被打断，重放时也在第 0.8 秒停下。

海报导出与回放封存各自完成。回放资源缺失时提示缺哪一段并续传，经理仍能拿走已生成的海报。回看时的暂停或拖动只改变观看位置，原会话记录保持可复查。

## 9 黑客松验收与演示

| 场景 | 可以直接观察的通过条件 |
| --- | --- |
| **意见不一致也能完成任务** | 用黄贴制造 **80／65／100**。保留冲突，经理直接导出 B 版。即使三方仍在发言、某项待验证或需求尚模糊，已生成版本均可下载。 |
| **需求确实能被问清** | 用文字向周总问“高级指哪里”，用语音追问“缩到手机大小先看见什么”。得到可定位的元素和标准，可原样转交或编辑后交给小乙，原话与改写都能回看。 |
| **评分有据可查** | 同一版按分项手算可复现三个总分。扩大黄贴让周总 −20、林尺 −35、阿唐 +15。未受影响的分项保留原值，缺少入口证据时显示待验证及分数依据。 |
| **员工真会停，也真能继续** | 奇数工单在 50% 停一次，拍桌后出现 QAQ，原工单续做。另测按钮、空格、文字、语音与重复催促。失败重试最多新增一个版本，导出图能看到指定图层的变化。 |
| **语音可打断且低延时** | 按第 7 节统计首字、首音、拍桌反馈与停播。打断后旧声音不复播，拒麦或 TTS 超时后仍能继续派工。 |
| **每个操作都能回放** | 录一局含改写、插话、静音、摸鱼、拍桌、对比、恢复和导出的会话。断网后重放两次，逐项对账动作和反馈，要求覆盖率 100%。每版图像哈希、三方分数和字幕顺序相同，按 1 倍速测声音切点与表情起点误差目标 ≤ 100 毫秒。 |
| **恢复与重复提交** | 摸鱼时刷新、重连后重复催促、工具回包迟到。当前工单与版本不被重复提交。回放可跨版本拖动，播放时外部模型、TTS 与改图调用数为零。 |

**建议的两分钟演示。** 从第 5 节的 A 版开场。先用 20 秒把“高级一点”原样转发，展示小乙的反问，再追问出具体目标。接下来的 50 秒让小乙执行黄贴工单，进度停在一半时请评委拍一下桌子，看 QAQ 和复工。再用 30 秒呈现甲方对同一张图的争执与三条分数，经理在林尺只有 65 分时点击导出。最后 20 秒从时间轴跳回刚才那一拍，同时对比改前与改后的海报。

**建议的动工顺序。** 第一阶段从新版 UI 打通“主题初稿 → 派工 → 摸鱼与复工 → 真改图 → 三方评分 → 任意版本导出”，同步写入事件日志。第二阶段接四个角色的定向对话、引用式争吵和可打断的中文语音。第三阶段封存媒体、完成离线回放与弱网恢复，并分别验收真实服务延时和本地演练的可完成性。
